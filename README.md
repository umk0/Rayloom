# Rayloom 0.6 — управление светом пространства

[Релизный план](docs/RELEASE-PLAN.md) · [Переход бренда](docs/BRAND-MIGRATION.md) · [Windows Setup и обновления](docs/INSTALLER-UPDATE.md) · [Переносимая сборка](docs/RELEASE-PACKAGE.md)

Для сохранённых профилей предыдущего прототипа предусмотрен перенос; каталоги профилей и plugin IDs совместимы.

Текущий renderer — **Electron + React + Mantine 9.7.4**, интерфейс Quiet Workspace
и выбранный логотип №2 Light Score. Перенос базовых экранов проверен на Windows:
138 тестов логики, 15 UI-сценариев и 5 сценариев редактора. Проверка других ОС,
DPI и пользовательская приёмка остаются впереди. [Результаты](docs/VERIFICATION-MANTINE-2026-10-29.md).
[План пересборки](docs/UI-REBUILD-2026-10-28.md),
[критерии UX-приёмки](docs/UX-ACCEPTANCE-2026-10-28.md).

[Проверки 0.6](docs/VERIFICATION-0.6.md) и [визуальный обзор 0.6](docs/UI-REVIEW-0.6.md)
относятся к предыдущему HeroUI-интерфейсу; они не подтверждают готовность новой версии.

Дальнейшее направление: [единый свет компьютера и дома, бренд и план этапов](docs/PRODUCT-PLAN.md).

Локальная сборка Windows x64. Ядро собирается из собственного форка OpenRGB 1.1 в `core/`. Новый интерфейс находится в `src/mantine/` и запускается через `src/main.tsx` внутри Electron 45. Нативные Qt-виджеты остаются скрытыми для совместимости с логикой исходных плагинов; отдельное окно OpenRGB не требуется.

## Запуск

Сборки интерфейса хранятся по правилу **текущая + предыдущая**. `npm run build`
публикует только успешный результат и автоматически удаляет более старые файлы.
[Хранение сборок и границы очистки](docs/BUILD-RETENTION.md).

`Launch.ps1` или `npm start`. После изменения renderer сначала выполните `npm run build`. По умолчанию открывается Mantine-интерфейс и включено автоматическое обнаружение реального оборудования. В «Настройки → Режим оборудования» можно выбрать виртуальную студию с тестовой лентой на 60 LED. Драйверы автоматически не устанавливаются. Пространственные кадры рассчитывает Rayloom, команды устройствам выполняет ядро OpenRGB; исходные эффекты и интеграции работают в нативных DLL. Конфигурация локальной сборки хранится отдельно от OpenRGB, в `runtime/user-data` внутри проекта. Electron, фоновый агент и launcher используют один каталог; его содержимое исключено из Git. Это также исключает расхождение AppData между процессами, запущенными из MSIX-приложения и через Планировщик Windows. Подробнее: [каталог данных и перенос профиля](docs/BACKGROUND-RUNTIME.md#data-directory).

Главный экран: группа → эффект → его параметры и яркость → «Применить». Параметры применяются явно; поля скорости и масштаба ограничивают ввод до допустимых значений. У каждого контроллера отдельная очередь свежего кадра: медленное устройство не задерживает остальные. Студия рассчитывает эффекты в worker; доступны цели 30/60/90/120 FPS и измеренные показатели отправки/драйверов.

Для сравнения и восстановления на время миграции сохранён прежний HeroUI renderer
(`legacy.html`, `src/legacy.tsx`). Переменная процесса `LUMEN_UI=legacy` выбирает его
при запуске Electron; без неё используется новый интерфейс. Это резервный путь
для разработки, использующий тот же профиль и фоновый движок, а не отдельный
набор настроек. Сборка включает оба входа.

Схема начинается в 2D. Кнопки **3D** и **На весь экран** открывают точную настройку: XYZ-ручки, повороты, zoom под курсором, Space/средняя кнопка для панорамирования, Alt для вращения, Ctrl для привязки и Shift для точного движения. **Показать всё**, **Найти выбранное**, F/Home возвращают далеко перемещённые устройства; Ctrl+Z отменяет последнее перемещение.

В разделе **Группы** выберите порты, сохраните группу и назначьте ей эффект. В **Устройствах** можно переименовать контроллер или его порт. **Подсветить** даёт три красных импульса примерно за три секунды и возвращает предыдущее состояние. Калибровка поддерживает шесть порядков RGB и яркость порта. Матрицы клавиатур поступают из ядра; ARGB-цепочки можно разделять на вентиляторы. Сцены сохраняют геометрию, группы, калибровку и эффект. Настройки аппаратного и виртуального режимов раздельны.

В «Расширения → Слои эффектов» доступны сложные сцены библиотеки 58 эффектов. Сцена может содержать несколько эффектов с отдельными назначениями зон. Сохранённые сцены доступны Scheduler и HTTP Hook как профили OpenRGB. Коррекция портов применяется к выводу основной студии (включая её OpenRGB Effects), SDK и Canvas; прямой вывод отдельных плагинов использует настройки самих плагинов.

У окна собственная панель: скрыть в трей, свернуть, развернуть/восстановить, закрыть редактор. **Крестик завершает Electron, а подсветка продолжает работать в отдельном движке Node + OpenRGB.** Повторный запуск редактора подключается к тому же движку. «Полностью завершить Rayloom» в настройках останавливает и движок. Полноэкранный редактор пространства занимает весь монитор; Escape сначала закрывает вложенное меню/диалог, затем возвращает обычное окно. Эти сценарии нового renderer входят в текущую приёмку. [Фоновый режим и автозапуск](docs/BACKGROUND-RUNTIME.md).

## Что доступно

- Редактор HTML Canvas: код, шаблоны, отдельный предпросмотр, параметры из meta-тегов, библиотека, импорт/экспорт и вывод на выбранную группу. Скрипт работает в отдельном renderer без сети и файлов; зависание не блокирует интерфейс. [Создание эффекта](docs/CANVAS-EFFECTS.md).
- Пространственная студия: 2D/3D, группы, кольца/ленты/матрицы, диапазоны LED, определение порта/LED, RGB-калибровка, пользовательские шаблоны и сцены.
- 13 эффектов Lumen, в том числе «Аврора», «Туманность», «Метеоры», «Угли», «Призма», «Прилив», «Светлячки» и «Орбита». Библиотека карточек с поиском и предпросмотром при наведении; все 58 нативных эффектов также доступны.
- Пошаговая калибровка порядка RGB: три вопроса о видимом цвете, изоляция выбранного порта, предварительная проверка и восстановление подсветки при отмене. Определение порта также временно гасит остальные устройства.
- Отключение устройства скрывает его из пространства, гасит его LED и сохраняет расположение и имена для последующего включения.
- [Каталог устройств](docs/DEVICE-CATALOG.md): 2257 записей поддержки и детекторов, 63 матрицы LED с исходными индексами, происхождением и SHA256. Число записей не равно числу проверенных моделей.
- Игровой приёмник health/ammo: локальный HTTP с токеном, GSI-конфигурация, тревога при низком здоровье. Реальная игра ещё не проверена.
- SDK v1: установка декларативных пакетов из папки, RGB-формулы с X/Y/Z и игровыми событиями, пример Reactor. [SDK и миграция](sdk/README.md), [продуктовое направление](docs/PRODUCT-DIRECTION.md).

- Effects: все 58 алгоритмов, индивидуальные настройки, палитры, аудиовход и 16 полос EQ, Custom Blink, группы Layers и режимы смешивания, GIF, выбор области Ambient мышью, редактор GLSL с проходами, текстурами, библиотекой, живым просмотром и ошибками компиляции.
- Visual Map: редактирование и перетаскивание зон, собственная форма LED, сетка, виртуальные контроллеры, сохранение и загрузка карт, изображения, градиенты и библиотека пресетов.
- Hardware Sync: источники датчиков, интервалы, цветовые пороги, назначения зон, яркость и заполнение по проценту. В виртуальном режиме источник явно обозначен как тестовый.
- E1.31: universes, каналы и назначения LED, автоматическая карта, multicast, запуск/остановка и счётчик UDP-пакетов.
- HTTP Hook: локальный сервер, GET/POST маршруты и запуск профилей.
- Scheduler: cron, готовые расписания, профили, включение и ручной запуск задач.
- Skin: палитры Electron, сохранение, автозагрузка, импорт/экспорт. Из QSS импортируются цвета; селекторы и геометрия Qt не воспроизводятся в HTML.

## Сборка

Требуются Node 24, Visual Studio 2022 Build Tools с x64 C++, Windows SDK и 7-Zip. Исходники восьми проектов и их подмодули уже находятся в рабочей папке. Не заменяйте их чистыми upstream-копиями: изменения форка находятся в этих checkout.

Из исходной папки:
```powershell
npm ci
npx install-electron
node scripts/bootstrap.mjs
npm run build
.\scripts\build-launcher.ps1
```

Qt 6.8.3, jom и LHWM wrapper проверяются по SHA256 из `docs/sources.lock.json`. Wrapper для реальных датчиков загружается, но в виртуальном режиме не исполняется.

qmake/jom требуют ASCII-пути. Для папки проекта с кириллицей создайте локальный junction с ASCII-именем и запускайте нативную сборку из него:
```powershell
New-Item -ItemType Junction -Path C:\rayloom-workspace -Target <путь-к-проекту>
Set-Location C:\rayloom-workspace
.\scripts\build-netfx-import.cmd
.\scripts\build-core.cmd
.\scripts\build-effects.cmd
foreach ($plugin in 'scheduler','http-hook','hardware-sync','e131','visual-map','skin') {
    & .\scripts\build-plugin.cmd $plugin
    if ($LASTEXITCODE -ne 0) { throw "Build failed: $plugin" }
}
```

Для изменений C++ без изменения `.pro` можно добавить `--incremental`. Скрипты сначала генерируют JSON-метаданные, затем moc, затем компилируют параллельно. Это предотвращает попадание пустых метаданных в DLL. JavaScript собирать из исходного пути, поскольку Vite разрешает junction.

Выход ядра: `core/release/Rayloom-Core.exe`; плагины: `plugins/*/release/*.dll`. При запуске DLL копируются в отдельный рабочий каталог ядра. Для независимой проверки можно задать `RAYLOOM_USER_DATA`. `RAYLOOM_MODE=virtual` явно выбирает виртуальное устройство, `RAYLOOM_MODE=hardware` — оборудование компьютера. Для изолированных прогонов используйте отдельный `RAYLOOM_USER_DATA`. Переменная окружения имеет приоритет над сохранённым режимом.

## Проверки

Логика задержанных ответов нового renderer проверяется отдельно командой
`node --test tests/mantine-layout-races.test.mjs`: сохранение, загрузка сцены,
переключение устройства, калибровка и смена режима. Эти тесты выполняют обработчики
с подставным IPC; они не подтверждают DOM, фокус, native fullscreen или железо.
Полная приёмка Mantine пока продолжается по [UX-критериям](docs/UX-ACCEPTANCE-2026-10-28.md).

```powershell
npm test
npm run test:core
npm run test:effects
npm run test:plugins
npm run test:media
npm run test:persistence
npm run test:studio
npm run test:runtime
npm run test:background
npm run test:canvas
npm run test:ui
npm run sdk:validate
```

Выполнять сетевые проверки последовательно: используется UDP 5568 и локальные HTTP 18764/19423. UI-тест использует установленный Playwright (путь можно задать через `LUMEN_PLAYWRIGHT_MODULE`) и изолированное виртуальное устройство. **`npm run test:hardware` меняет физическую подсветку**: только после разрешения пользователя и завершения существующего фонового движка; тест сохраняет исходный кэш цветов/режимы и восстанавливает их в finally. Для проверки работающего движка используйте `node scripts/verify-live-runtime.mjs --allow-physical`: этот сценарий подключается к существующему владельцу и не запускает второе ядро. Отдельная проверка обнаружения без эффектов: `node scripts/probe-hardware.mjs --all-plugins`, также только без другого ядра. Отчёты сохраняются в `artifacts/`. Подробности: [проверки 0.5](docs/VERIFICATION-0.5.md), [проверки 0.4](docs/VERIFICATION-0.4.md), [базовые проверки 0.3](docs/VERIFICATION.md).

## Совместимость и исходники

Plugin API 5, IID и vtable исходного OpenRGB не изменены. Загрузка неизменённой официальной Effects DLL проверяется отдельно. Совместимость бинарного плагина зависит также от Windows x64, Qt и компилятора; неизвестные будущие версии API автоматически совместимыми не становятся.

Электронные панели семи плагинов используют дополнительный JSON-контракт через существующий `OnSDKCommand`. Для нового эффекта достаточно декларативного manifest SDK. Для нативной интеграции плагин может сохранить стандартный ABI и реализовать JSON-адаптер; его React-панель регистрируется в исходниках приложения. Автоматическая загрузка произвольных сторонних веб-панелей пока не реализована. Описание: [PLUGIN-PROTOCOL.md](docs/PLUGIN-PROTOCOL.md), [матрица переноса](docs/PLUGIN-MIGRATION.md).
