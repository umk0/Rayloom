# Переносимая Windows-сборка Rayloom

Инженерный этап от 13 ноября 2026. Это проверяемый комплект приложения без
установщика и автоматического переноса старого профиля. Публичным релизом он
пока не объявляется.

## Сборка

`npm run build:portable` сначала проверяет TypeScript и собирает renderer через
обычный механизм хранения двух версий, затем создаёт пакет в
`release-history/current/`. Там находятся `Rayloom.exe`, Electron, `app/dist`,
ядро OpenRGB, семь нативных плагинов, отдельный Node 24.15.0 и краткоживущий
launcher фонового агента. Пакет содержит GPL, доступные лицензии плагинов,
Electron/Chromium, Node, Mantine, Monaco и шрифта. Для Node закреплены исходник
[v24.15.0 LICENSE](https://github.com/nodejs/node/blob/v24.15.0/LICENSE) и
SHA256 `4573185d56580da2b890ba34a85a409257640f1c5632eade4300137266194d18`.

`release-history/previous/` хранит только предыдущий полный комплект. В пакет
попадают только файлы из проверенного manifest текущего renderer: архивные JS
ресурсы для уже открытого редактора не загрязняют новый выпуск.
Повторная сборка с теми же входными файлами не меняет его. Пакет содержит
`release.json` с SHA256 каждого файла; перед ротацией хеши текущей версии
проверяются. При незавершённой транзакции сборка останавливается, оставляя
файлы для восстановления. Каталог `release-history/` исключён из Git.
Одинаковые файлы двух версий могут иметь общие жёсткие ссылки для экономии
места; файлы опубликованного комплекта нельзя изменять на месте.

Профили, сцены, макеты, токены и журналы в пакет не копируются. Поставляемая
версия хранит данные в `%LOCALAPPDATA%\Rayloom`; локальная сборка из исходников
по-прежнему использует `runtime/user-data`. `LUMEN_USER_DATA` сохраняет
приоритет. Данные не лежат внутри `current` или `previous`, поэтому их не удаляет
ротация версий. Пока нет мигратора, запускать собранный пакет на реальном железе
одновременно со старым фоновым агентом нельзя: у них разные каталоги профилей и
они могут открыть одно оборудование.

## Проверка без управления светом

`npm run test:portable` сверяет пакет с manifest, проверяет оба launcher в
режиме `--check-only`, запускает отдельный агент с виртуальным устройством,
дожидается семи плагинов и штатно завершает его. Этот тест не открывает окно и
не обращается к физическим RGB-контроллерам. `npm test` проверяет ротацию,
отсутствие профилей и отказ при повреждённом комплекте.

На 13 ноября текущий комплект содержит 335 файлов плюс manifest; предыдущий
комплект сохранён. Нативный виртуальный прогон из `release-history/current`
обнаружил одно устройство и семь плагинов. Общий unit-прогон: 374 passed,
0 failed, 1 skipped. Новое ядро и агент именуются Rayloom; повышенная задача
локальной сборки перенесена без смены каталога профиля. Физический запуск нового
ядра и проверка входа в Windows ещё не выполнены.

Перед распространением ещё нужны ручная проверка GUI на чистой машине,
установщик, перенос профиля и автозапуска, восстановление предыдущей версии,
полный аудит лицензий и исходников форка, проверка безопасности и подпись
дистрибутива. Состояние задач — в [релизном плане](RELEASE-PLAN.md).
