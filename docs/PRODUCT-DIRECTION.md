# Направление LumenRGB

Актуальные требования, варианты нового имени и порядок следующих этапов:
[PRODUCT-PLAN.md](PRODUCT-PLAN.md). Документ ниже описывает исходную модель
этапа 0.3; его исторические количества и статусы не заменяют проверки 0.5.

Главный сценарий: единая подсветка всего пространства. Точная настройка устройств и игровые события входят в ту же модель сцены.

## Рабочий сценарий 0.3

Обнаружение → компоненты и матрицы → расположение → группа → эффект → сохранение сцены.

На главном экране — группа, яркость, запуск, пространство и выбор атмосферы. Нативные технические панели вынесены в «Расширенные инструменты», включая все 58 эффектов и шесть других портов плагинов.

### Пространственная модель

Устройство OpenRGB → зона → один или несколько компонентов → локальные координаты каждого LED → масштаб → повороты X/Y/Z → перенос → общие мировые координаты.

Например, 36 LED одной ARGB-зоны можно разделить на три вентилятора по 12 LED. Каждый получает кольцевую матрицу, собственное положение и наклон; группа объединяет их с видеокартой и клавиатурой.

Точная матрица подключённой клавиатуры берётся из ядра с сохранением пропусков и физической нумерации. Обычный ARGB-разъём не сообщает марку и форму подключённого вентилятора. Для него применяются пользовательская калибровка и шаблоны.

Справочник OpenRGB 1.1 содержит 312 записей поддержки контроллеров/устройств. Это не 312 гарантированно точных геометрий и не автоматическое распознавание всего оборудования. Указаны источник, дата получения и SHA256.

### Сочетание старых и новых эффектов

Пространственные эффекты и SDK получают X/Y/Z. Оригинальные эффекты OpenRGB работают через Visual Map: уже повёрнутые LED проецируются на выбранную плоскость XY/XZ/YZ, образуя общий виртуальный холст 128 × 128. Это проекция объёма, а не превращение каждого старого алгоритма в трёхмерный.

## Кандидаты в отличительные возможности

Это продуктовые гипотезы, а не доказательство отсутствия аналогов у конкурентов.

| Возможность | Статус |
|---|---|
| Единая 3D-геометрия каждого LED, независимые наклоны вентиляторов и устройств | Реализована модель, редактор, drag/orbit, три проекции и выходные кадры |
| Калибровка «выбрать LED → подсветить → исправить координату» | Реализована; возвращает захваченные цвета после 750 мс |
| Разделение одного ARGB-канала на компоненты | Реализовано через диапазоны LED; не меняет аппаратный размер зоны |
| Сохраняемые матрицы и шаблоны в плагинах | Локально реализовано; общая проверенная база сообщества ещё нужна |
| Игровые события поверх атмосферы с возвратом к ней | Health/ammo и одно правило тревоги работают; универсальный граф правил ещё не реализован |
| Перенос сцены между разными ПК через роли «клавиатура / корпус / стол» | Следующий этап: мастер сопоставления, без угадывания серийных номеров |
| Автоматическая калибровка камерой, распознавание порядка LED | Исследование, не реализовано |
| Слои с приоритетами игры/музыки/температур и плавным переходом | Нативные Layers доступны; общий пространственный compositor ещё не реализован |

SignalRGB уже поддерживает вращение объектов в плоском Layout: [официальное руководство](https://docs.signalrgb.com/guides/device-configuration/how-to-create-a-layout/). Поэтому отличительная идея здесь — реальные координаты и повороты по трём осям, калибровка и общая модель для эффектов и интеграций.

## Дальнейшая проверка

Физические выходные цвета, сон/пробуждение, подключение во время работы, нагрузка больших матриц, реальные аудиоустройства и игровая сессия требуют отдельных прогонов. Сейчас локальная разработческая сборка, не готовый публичный установщик.
