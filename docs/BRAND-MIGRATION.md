# Переход бренда на Rayloom

Начат 13 ноября 2026 по решению пользователя: старое имя и изображения должны
исчезнуть из продукта и исходников. Переход выполняется перед установщиком.
Сохранённые сцены, макеты, черновики и автозапуск нельзя терять при смене
идентификаторов.

## Уже сделано

- Оба интерфейса используют существующую иконку Rayloom. Девять старых файлов
  `public/brand/lumen*` удалены после проверки отсутствия ссылок в исходниках.
- В основном Mantine больше нет видимой кнопки с прежним названием; импорт
  подписан как перенос сцены из прежней версии.
- Имя npm-пакета, автор демонстрационного SDK-пакета, имя новой игровой
  конфигурации, заголовок Canvas host и Windows AppUserModelID сменены на Rayloom.
- Новый ключ черновика HTML-эффекта имеет префикс `rayloom`; старый ключ читается
  при первом открытии, затем черновик записывается под новым именем.
- Нативное ядро собрано как `Rayloom-Core.exe` и показывает имя Rayloom; его
  Windows-ресурс использует `rayloom.ico`. Фоновый launcher собран как
  `Rayloom-Agent.exe`. В текущем переносимом комплекте нет EXE и изображений
  со старым именем.
- Повышенная задача текущего пользователя переведена на `Rayloom-Agent.exe`
  без перезапуска работающей подсветки. Сохранены исходный каталог
  `runtime/user-data`, режим hardware и флаги автозапуска. Перед переносом
  параметры и XML задачи сохранены в
  `runtime/profile-backups/brand-migration-20261113-223439/`.
- Встроенный SDK-пример использует ID `org.rayloom.reactor`; сохранённые сцены
  со старым ID и параметрами читаются через миграцию. Фильтр библиотеки эффектов
  тоже переводит сохранённый старый источник в `rayloom`.
- Упаковщик берёт только файлы из проверенного manifest текущего renderer,
  поэтому архивные JS-ресурсы не попадают в новый комплект. `npm run test:core`,
  `npm run test:portable` и `npm test` прошли: 374 passed, 0 failed, 1 skipped.

## Ещё требуется для полного перехода

1. Дождаться штатной остановки ныне работающего `LumenRGB-Core.exe` и проверить
   запуск нового ядра на реальном оборудовании с тем же профилем. Старый бинарник
   остаётся в рабочем дереве до этой проверки, но не входит в новый комплект.
   Проверка задачи при следующем входе Windows и восстановление сцены открыты.
2. Заменить внутренние имена IPC, переменных окружения, CSS-классов и API
   renderer. Старые идентификаторы профиля и виртуального устройства оставить
   только в явно выделенном коде миграции. Для переносимого пакета нужен
   однократный импорт `runtime/user-data` в `%LOCALAPPDATA%\Rayloom` с откатом.
   Переименование device ID без миграции может потерять привязки LED в сценах.
3. После полного переноса обновить README и архивные отчёты,
   оставив только корректные исторические сведения в миграционной инструкции.
4. Проверить `rg` по активному коду и конечному пакету: старый бренд должен
   встречаться только в явно обозначенном импортере старых данных до завершения
   поддержки миграции. После этого удалить и эти остатки. Пройти чистый запуск,
   импорт старого профиля, повторный запуск, автозапуск и откат.

Пакеты `OpenRGB*` и упоминание OpenRGB в благодарностях сохраняются: это
происхождение исходников и совместимость сторонних плагинов, а не прежний бренд
нашего приложения. В обоих собранных Windows-комплектах старых изображений уже
нет; предыдущий renderer в `build-history/` ещё хранит их до следующей ротации.

После переноса task ID прежней версии отсутствует, новая задача находится в
состоянии Ready. Процесс старого ядра (PID 15184 на момент проверки) не
останавливался. Новый `%LOCALAPPDATA%\Rayloom` ещё не создан; запуск переносимого
пакета на физическом оборудовании до переноса профиля остаётся отдельным этапом.
