# Установка и обновление Rayloom

Windows Setup — самораспаковывающийся EXE. Упаковщик NSIS не показывает страницы;
пользовательский установщик открывается в отдельном окне Electron. Он выбирает
каталог программы, каталог профиля и при необходимости копирует профиль из
предыдущей сборки. Файлы профиля остаются вне папки программы.

`shared/install-release.mjs` проверяет manifest и SHA-256 каждого файла,
хранит `current` и `previous`, выполняет замену через staging и умеет
откатывать версию. Новая сборка не заменяет работающий движок. Удаление
по умолчанию оставляет профиль и предлагает удалить его отдельно. Задача
автозапуска удаляется до удаления программы.
При переносе профиля установщик предлагает Windows UAC и переносит повышенную
задачу на новый каталог после проверки её владельца и параметров. Отмена UAC
оставляет прежнюю задачу на месте и показывает предупреждение.

Приложение проверяет `Umk0/Rayloom` при запуске и раз в шесть часов. Для
Windows-релиза нужны два assets с одинаковой версией:

```text
Rayloom-Setup-X.Y.Z.exe
Rayloom-Setup-X.Y.Z.exe.sha256
```

Тег релиза — `vX.Y.Z`; версии сравниваются численно. Если стабильного релиза
пока нет, проверяются опубликованные предварительные релизы. Загрузка проверяется по
размеру и SHA-256. После выбора «Установить и перезапустить» фоновый движок
закрывается и запускается Electron Setup. Установщик подхватывает путь
существующей установки из HKCU.

Локальная сборка:

```powershell
npm run build
node scripts/build-portable-release.mjs
.\scripts\build-installer.ps1
```

Проверка профиля и транзакции: `node --test tests/install-release.test.mjs
tests/update-service.test.mjs`. Запуск Setup с реальным оборудованием и
реальная миграция повышенной задачи из старой переносимой версии требуют
отдельной приёмки перед публичным релизом. Не публикуйте бинарный релиз, пока исходники
ядра и плагинов не доступны в репозитории и не пройдена эта приёмка.
